## The flight-test program

The names are falconry: the house keeps the birds, the falconer trains them,
the tunnel measures the flight. One loop, several birds — a local-AI stack
where every claim is measured:

| Repo | Role | What it does |
|---|---|---|
| 🏰 [**minder**](https://github.com/xyzzing/minder) | the tower | Governed agent runtime: capture, memory, staged escalation, policy, operator console. **Start here** — a two-minute try is in its README. |
| 🏠 [**mews**](https://github.com/xyzzing/mews) | the house | Contract-drift tripwires, full-loop shakedown, program map. |
| 🔥 [**cupola**](https://github.com/xyzzing/cupola) | the furnace + watch-dome | Certify-before-serve and work backpressure above the engine; deterministic llama-server lifecycle on AMD Radeon *(formerly sinter)*. |
| 🧭 [**windroos**](https://github.com/xyzzing/windroos) | the rose | The repo agent: bounded coding tasks for a cheap local model, judged by an independent verifier. |
| 🛩 [**kernelbench-hip**](https://github.com/xyzzing/kernelbench-hip) | the proving ground | First KernelBench-protocol results on AMD gfx1100 (RX 7900 XTX). |
| ⚙️ [**Strata**](https://github.com/xyzzing/Strata) | the engine | The HIP/AMD inference-engine fork this stack is measured on. |

*Private for now: valkenier (the falconer — training), windtunnel (the
tunnel — measurement rooms).*

## Open-source mission

Make sophisticated tooling **transparent, auditable and usable by
organisations without enterprise budgets**. Today that means local AI agents
you can measure and govern: what a task costs in energy, whether the agent
finished it, and where its reasoning budget went.

Issues and PRs raised on PyTorch and AMD LLVM.
